# I18n Design

## Goal

Add Chinese and English localization to the mobile app. The app must follow the user's phone system language: Chinese system languages use Simplified Chinese, and all other system languages use English.

## Scope

- Localize the in-app user interface with `i18next`, `react-i18next`, and `expo-localization`.
- Localize the app display name:
  - Chinese: `订单台账`
  - English: `Order Ledger`
- Localize native permission strings for camera/photos/files where Expo app config supports them.
- Replace public wording that mentions Taobao with more generic wording such as supplier purchase, online purchase, purchase proof, or purchase document.
- Keep CSV headers and import column aliases compatible with the current Chinese business files for this iteration.

## Architecture

Add a focused `src/i18n/` module. `resources.ts` owns translation resources and supported language types. `index.ts` initializes i18next, detects the device language with `expo-localization`, and exports a typed `useAppTranslation` helper plus a direct `translate` function for non-component code.

React components will call `useAppTranslation()` and render `t("key")` values. Domain validators that currently return Chinese strings will be moved to stable error codes plus localized formatting where practical; if a full refactor would be too broad, the first pass can localize workspace-level alerts while preserving domain behavior tests.

Native app name localization will use Expo `locales` files. Each locale JSON includes `CFBundleDisplayName` for iOS and `app_name` for Android. The base `name` remains Chinese for compatibility, with English provided through locale resources.

## Copy Rules

- Do not use Taobao-specific wording in UI or marketing copy.
- Use "supplier purchase", "purchase proof", "purchase document", and "online purchase" for English.
- Use "供应商买入", "买入凭证", "采购资料" for Chinese.
- English copy should be concise and operational, not marketing-heavy.

## Testing

- Add unit tests for language detection and fallback.
- Add unit tests for interpolation, including counts and dynamic labels.
- Run `pnpm typecheck`.
- Run `pnpm test`.
- Run Android build verification after UI replacement.
